# PGN end-to-end testing and acceptance criteria

**Testing status (2026-10-11):** Sections marked *Automated* are covered by `node tests/run-tests.js` (mocked Google services, synthetic data) and/or the browser pass described in `TEST_RESULTS.md`. Sections marked *Live* must be executed in a user-controlled private Google environment with fictional records. Record `PASS`, `FAIL` or `NOT EXECUTED` with steps, expected/observed results, severity and reproduction.

1. **Forms intake** — *Automated 1.1–1.11; Live.* Submit one synthetic multi-concern response; verify row timestamp, one submission ID, multiple issue rows with exact supporting snippets (curly quotes preserved). Replay the trigger: no duplicate rows, no extra AI call. Delete a response row and submit again: new submission gets a suffixed ID, nothing dropped. Rename a Form question: submission stored as "Header Mismatch". Run `pgnReprocessMissingSubmissions` after deleting a submission's issue rows: rows restored.
2. **AI failures** — *Automated 2.1–2.6; Live for real HTTP errors.* Invalid JSON, empty output, safety block, 429 (retried), 500 (retried then fallback), 400 (not retried), network error, daily budget, over-length text. Confirm one "AI Failed" row with the full text, no auto-grouping, logs with no confidential text or keys.
3. **Category corrections** — *Automated 3.1–3.3; Live for model behaviour.* Correct an Uncategorized dues issue to Finance: category, VP of Finance, correction row (date, ID, summary, previous, corrected), unchanged text/summary, group link re-evaluated, counts exact. Re-correct: newest example wins and only it appears in the next prompt. Generic single-word overlaps are not sent.
4. **Manual grouping** — *Automated 4.1–4.4; Live.* Assign to a compatible group, run `syncRecurringIssues`: choice persists. Ungroup explicitly: persists. Reject cross-category and archived targets. Merge two same-category groups: issues moved, source `Merged` with "Merged into GRP-x", count 0, notes retained, system note on target, new matching submissions land on the survivor.
5. **Action log** — *Automated 5.1; Browser.* Add two notes (same client token twice → one row). Delete one: only in Deleted Notes with deleted-at/by. Restore: original text/time unchanged, restored-at set. Reject malformed/nonexistent IDs; repeat delete is a no-op.
6. **Group management** — *Automated 6.1; Browser.* Priority/status persist; invalid values rejected; merged groups read-only; action notes never change issue status.
7. **Leadership brief** — *Automated 7.1–7.3; Live for wording.* 0 actions → "No leadership actions have been recorded…" regardless of model text; with notes → request contains active notes only (deleted never); malformed model output → safe fallbacks; identical context → cached; archived group rejected. Live: plans-only vs completed-step notes must be attributed accurately.
8. **Web dashboard** — *Browser pass; Live for Apps Script iframe.* All tabs, search, category/urgency/status/method filters, local-date range filters, counts, detail pages, full-submission viewer, keyboard operation (Tab/Enter on rows, focus to heading), back button, logo, responsive 375 px, graceful API errors.
9. **Privacy/security** — *Automated 9.1–9.4; Live.* Formula strings stored as text; prompt injection passed as data; every endpoint denies non-allowlisted callers; `doGet` denial page; blank-caller policy. Live: second-account access denied by deployment; `testPGNAuthorization` shows caller visible; Form has no e-mail collection; Sheet shared with no one; no keys in exports.
10. **Race/scale** — *Automated 10.1–10.2; Live.* 1,000 issues sync in ≤ 6 reads / ≤ 6 writes; dashboard load reads once and never writes; lock contention yields a friendly error. Live: three rapid submissions; a thousand-row sheet within the 6-minute trigger limit.
11. **Portability** — *Automated 11.1–11.2; Live.* `pgnSetupProject` creates/completes sheets non-destructively; `pgnInstallFormTrigger` idempotent. Live: recreate on a new account per `SETUP.md` §B with fresh credentials and verify form-to-dashboard flow and redeployment.

No claim of full coverage is made for live Google behaviour; see `TEST_RESULTS.md` §4 for the exact NOT EXECUTED list.
